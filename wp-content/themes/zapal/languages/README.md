# Переводы темы ZAPAL

Источник: PHP-файлы темы из GitHub main c51948d3251a98bc15984f2bc460b21374fc59c8.
Text domain: `zapal`, источники на украинском.

## Установка

Распаковать каталог `zapal/` поверх `wp-content/themes/zapal/`.
`inc/supports.php` УЖЕ регистрирует перевод темы через
`load_theme_textdomain('zapal', get_template_directory() . '/languages')`.
Повторно вызывать `load_textdomain()` не нужно.

Внутри темы WordPress загружает `languages/<locale>.mo`:
- `uk.mo` (стандартный WordPress locale для украинского)
- `ru_RU.mo`
- `en_US.mo`
- `en_GB.mo`
- `uk_UA.mo` (совместимость с нестандартно настроенным locale Polylang)

Файлы `<locale>.po` предназначены для редактирования переводов.
`zapal.pot` является шаблоном исходных строк.

### Важное отличие от глобальных переводов WordPress

В папке `wp-content/languages/themes/` действуют имена
`zapal-ru_RU.mo`, `zapal-en_US.mo`, и т.д. Примеры из `languages.zip`
относятся к **глобальной** папке, а не к папке самой темы.

Уже имевшиеся `zapal/languages/zapal-ru_RU.po/.mo` и
`zapal/languages/zapal-en_US.po/.mo`, `zapal-en_GB.po/.mo` устарели:
это имена для ГЛОБАЛЬНОЙ директории. Они не используются при
`load_theme_textdomain(..., /languages)` и могут быть удалены отдельно
из репозитория после проверки. Архив поверх темы ничего не удаляет.

## Граница локализации

Переведены статические вызовы `__()`, `esc_html__()`, `esc_attr__()`
и им подобные в PHP. Контент ACF (названия, описания, категории,
условия доставки) локализуется отдельно посредством ACF/Polylang.
JS-сообщения, включая обратную связь по формам, остаются задачей
отдельной интеграции с JS; файл `main.js` не изменялся, чтобы не
перетирать текущую работу над отправкой заявок.
